# A1 1 기술 학습서 · 용어와 구현 해설

## 1. 미션 전체의 구조

이 미션은 데이터를 읽는 일부터 설명 가능한 고객 전략을 제안하는 일까지 이어진다.

```text
허가된 표본 → 거래 정제 → 상품 조인 → 이미지·텍스트 피처
          → 결측·이상치 검토 → 통계·차트 → 고객 RFM → 인사이트·검증
```

| 용어 | 뜻과 이번 미션에서의 역할 |
| --- | --- |
| 이커머스(E-commerce) | 온라인 상거래 영역. 현재 데이터는 판매 채널을 임의 해석하지 않고 전체 채널을 사용한다. |
| 멀티모달(Multimodal) | 숫자·범주·날짜·텍스트·이미지처럼 표현 방식이 다른 자료를 함께 다루는 것. |
| 데이터 분석(Data analysis) | 구조·분포·관계를 조사하고 질문에 답하는 과정. 계산 결과와 해석을 함께 남긴다. |
| EDA(Exploratory Data Analysis) | 탐색적 데이터 분석. 먼저 구조·결측·분포·관계를 확인하며 가설을 만든다. |
| 파이프라인(Pipeline) | 입력부터 결과까지 이어지는 재현 가능한 처리 단계. |
| 전처리(Preprocessing) | 자료형 변환·유효성 확인·정제처럼 분석 전에 의미를 맞추는 처리. |
| 피처/특성(Feature) | 분석·예측에 사용할 변수. 원본 열과 이미지 평균 같은 파생 열이 있다. |
| 피처 엔지니어링 | 원본을 분석 목적에 맞는 변수로 바꾸는 설계·계산. |
| 비즈니스 인사이트 | 관측 수치에서 행동할 이유를 찾고 실행·검증을 연결한 해석. 효과의 증명과는 다르다. |
| 컴퓨터 비전(CV) | 이미지·영상 정보를 다루는 분야. 여기서는 신경망 대신 픽셀 통계만 계산한다. |
| 자연어 처리(NLP) | 언어를 계산 가능한 형태로 다루는 분야. 여기서는 길이·공백 기준 단어 수만 사용한다. |
| 머신러닝(ML) | 자료에서 규칙을 학습해 새 사례를 예측하는 방법. 모델 학습은 이번 필수 구현에 포함하지 않는다. |

## 2. 표와 자료형

| 용어 | 의미·예시·주의점 |
| --- | --- |
| Dataset / 데이터셋 | 분석에 쓰는 자료 묶음. 파일 하나 또는 여러 관계 테이블일 수 있다. |
| Row / 행 / 관측 | 분석 단위 하나. 구매 상품 행과 주문·구매일·고객은 서로 다르다. |
| Column / 열 / 변수 | 각 관측의 속성. price·t_dat·category 등이 해당한다. |
| Schema / 스키마 | 열 이름·자료형·키·의미에 대한 약속. 같은 숫자라도 단위를 확인해야 한다. |
| 수치형(Numeric) | 크기와 산술이 의미 있는 값. 거래금액, 문자 수 등이 해당한다. |
| 범주형(Categorical) | 상품군처럼 구분을 나타내는 값. 범주 번호를 연속 측정값처럼 평균내지 않는다. |
| 날짜형(Datetime) | 달력일·시각을 나타내는 자료형. 원래 문자열을 변환해 날짜 연산을 한다. |
| 문자열(String) | 문자들의 순서. ID·상품명에 사용한다. `00123`을 숫자로 읽으면 선행 0이 사라진다. |
| Boolean / 불리언 | True/False. 유효 행·대치 대상·이상치 여부를 표현한다. |
| dtype | 배열·열의 자료형. 계산 정밀도와 메모리 사용량에 영향을 준다. |
| CSV | 쉼표 구분 텍스트 표. 저장 자체에는 문자열 ID나 날짜 의미가 자동 보장되지 않는다. |
| DataFrame | Pandas의 행·열 표. 열마다 자료형이 다를 수 있다. |
| Series | Pandas의 한 열에 해당하는 인덱스 있는 자료 구조. |
| Index / 인덱스 | 행의 정렬·연결 기준인 레이블. 고객 ID와 같은 개념이라고 가정하지 않는다. |
| NaN / NA / NaT | 수치·일반·날짜의 결측 표현. 결측과 실제 0을 구분한다. |
| 유한값(Finite) | NaN과 양·음의 무한대가 아닌 값. 금액은 유한한 양수여야 한다. |
| 형 변환(Casting) | 문자열 날짜·금액을 적합한 자료형으로 변환. 실패를 기록해야 한다. |

`head()`는 앞부분 예시, `info()`는 자료형·결측 구조, `describe()`는 요약 통계를 확인한다. 예시 몇 행만 보고 전체 데이터의 결측·오류 여부를 단정하지 않는다.

## 3. 분석 단위와 조인

| 용어 | 뜻과 실패하기 쉬운 부분 |
| --- | --- |
| 거래 단위 | 구매 상품 행 기준. 같은 고객의 같은 날짜에도 여러 행이 있을 수 있다. |
| 상품 단위 | 상품 ID당 한 행. 이미지·텍스트 관계를 거래 수만큼 중복 계산하지 않는다. |
| 고객 단위 | 고객당 한 행. RFM·그룹 프로파일·고객 상관을 계산한다. |
| 월 단위 | 월별 구매금액 합계. 범위가 확인된 완전한 달을 비교한다. |
| Key / 키 | 두 표를 연결하거나 행을 식별하는 값. 현재 조인 키는 article_id다. |
| Join / Merge | 키로 여러 표를 연결하는 연산. 상품 메타데이터를 거래에 붙인다. |
| Left join / 왼쪽 조인 | 왼쪽 거래를 유지하고 일치하는 상품 정보를 추가한다. |
| Many-to-one / 다대일 | 거래 여러 행이 상품 한 행에 대응한다. 상품 키 중복은 거래 수·합계를 늘릴 수 있다. |
| 일치율 / 미매칭 | 상품을 찾은 거래 비중과 찾지 못한 거래. 미매칭을 구매 무효로 처리하지 않는다. |
| 카디널리티(Cardinality) | 값·관계의 개수 구조. 여기서는 상품 키의 고유성과 관계가 중요하다. |
| 무결성(Invariant) | 처리 전후 지켜야 할 조건. 거래 행 수·순서·금액 합계가 예다. |
| GroupBy | 그룹별로 나누어 집계하거나 같은 그룹 통계를 되돌리는 연산. |
| agg | 그룹마다 요약 행을 만드는 집계. 고객별 Monetary 합계 등에 쓴다. |
| transform | 원래 행 수에 맞춰 그룹 통계를 돌려준다. 그룹 평균 대치에 쓴다. |
| map | 키에 맞는 작은 값·피처를 각 행에 연결한다. 거래별 이미지 배열 복제를 피한다. |
| nunique | 중복을 뺀 값 수. 고유 구매일·주문 수를 계산한다. |

조인의 핵심은 값이 붙었다는 사실과 집계가 보존됐다는 사실을 함께 확인하는 것이다. Pandas는 null 키끼리도 연결할 수 있으므로 빈 상품 키를 먼저 제외한다. 금액은 부동소수점 오차를 고려해 `np.isclose(rtol=1e-12, atol=1e-10)`로 비교한다.

## 4. NumPy 배열·벡터화·메모리

| 용어 | 의미 |
| --- | --- |
| ndarray | NumPy의 다차원 배열. 대체로 동일 dtype의 원소를 다룬다. |
| Shape | 각 축 길이. RGB 이미지 한 장은 (H,W,C), 배치는 (N,H,W,C). |
| Dimension / ndim | 축의 개수. 배치 이미지 배열은 4차원이다. |
| Axis / 축 | 계산을 진행·축소할 방향. `(1,2,3)`을 축소하면 이미지 축 N은 남는다. |
| Vectorization / 벡터화 | 원소별 Python 호출을 배열 연산으로 표현하는 것. 내부의 반복 자체가 사라지는 것은 아니다. |
| Reduction / 축소 연산 | 여러 원소를 평균·합·표준편차 같은 적은 수의 값으로 요약한다. |
| Broadcasting | 모양이 다른 배열을 규칙에 따라 호환시켜 계산한다. 스칼라로 모든 픽셀을 나누는 정규화가 예다. |
| Stack / 쌓기 | 같은 모양의 이미지들을 새로운 N축으로 모은다. 실제 메모리 복사가 생길 수 있다. |
| Batch / 배치 | 동시에 처리하는 제한된 묶음. 전체 이미지를 한 번에 적재하지 않는다. |
| float32 / float64 | 원소당 각각 4·8바이트인 부동소수점 자료형. 정밀도와 메모리를 교환한다. |
| Strides | 축을 한 칸 이동할 때의 바이트 간격. 모양이 같아도 메모리 접근은 다를 수 있다. |
| Contiguous / 연속 배열 | 원소가 특정 순서로 연속 배치된 상태. 슬라이스가 항상 연속인 것은 아니다. |
| View / 뷰 | 원본 메모리를 공유하는 배열 표현. 변경이 원본에 영향을 줄 수 있다. |
| Copy / 사본 | 별도 메모리의 데이터. 분석용 보정 사본을 만들 때 원본 보존에 사용한다. |
| Boolean mask | True인 행·원소만 선택하거나 갱신하는 배열. 대치 대상 범위를 제한한다. |
| 고급 인덱싱 | 인덱스 배열 등으로 선택하는 방식. 이미지 축소에 사용하며 복사가 생길 수 있다. |
| nbytes | 배열 원소의 메모리 바이트 수. 프로세스 전체 메모리와는 다르다. |
| Cache / 캐시 | CPU의 빠른 임시 기억 공간 또는 재사용 결과 저장. 접근 순서가 성능에 영향을 준다. |
| SIMD | 한 명령으로 여러 데이터 원소를 처리하는 CPU 최적화. CPU·NumPy 빌드·연산에 따라 선택된다. |
| I/O | 파일·네트워크의 읽기/쓰기. NumPy 통계가 빨라도 이미지 읽기가 병목일 수 있다. |
| 병목(Bottleneck) | 처리 시간을 제한하는 단계. 측정 없이 가장 느린 곳을 확정하지 않는다. |

예를 들어 다음 배열은 두 이미지 모두 평균과 모집단 표준편차가 0.5다.

```python
import numpy as np
images = np.array([[[0, 0], [1, 1]], [[0, 1], [1, 0]]], dtype=np.float32)
images.mean(axis=(1, 2))  # [0.5, 0.5]
images.std(axis=(1, 2))   # [0.5, 0.5]
```

배열의 축을 올바르게 고르는 것과 메모리 크기를 제한하는 것은 별도의 설계다. Broadcasting은 불필요한 입력 복제를 줄일 수 있지만 결과·중간 배열이 커지면 메모리를 많이 쓸 수 있다. [NumPy broadcasting](https://numpy.org/doc/stable/user/basics.broadcasting.html)

SIMD는 지원 CPU에 맞는 내부 커널을 선택하는 최적화다. 모든 연산에 적용되거나 동일 속도 배수가 보장되는 것은 아니다. [NumPy CPU/SIMD](https://numpy.org/doc/stable/reference/simd/index.html)

메모리 계산은 `원소 수 × 원소당 바이트`다. RGB 1024×1024 한 장은 float32로 12MiB, float64로 24MiB다. 기본 32장 배치의 32×32×3 float32 배열 자체는 393,216바이트=384KiB다. 원본 디코딩·사본·stack·임시 계산의 메모리는 추가된다. 고객 100만 명이 이미지 100만 장이라는 뜻은 아니므로 고유 상품 수를 먼저 센다.

## 5. 이미지와 텍스트 피처

| 용어 | 설명과 한계 |
| --- | --- |
| Pixel / 픽셀 | 이미지의 위치별 값. 값 범위와 채널 수를 확인해야 한다. |
| Resolution / 해상도 | 이미지의 가로·세로 픽셀 수. 해상도가 커지면 읽기·계산 메모리가 늘어난다. |
| Grayscale / 회색조 | 명암 한 채널. 계산 모양을 맞추기 위해 RGB 세 채널로 반복한다. |
| RGB | 빨강·초록·파랑 세 채널. 모든 채널을 합쳐 하나의 평균·표준편차를 만든다. |
| RGBA / Alpha | RGB와 투명도 채널. 현재는 알파를 제외하며 배경 합성 효과를 계산하지 않는다. |
| 정규화(Normalization) | 픽셀 범위를 0~1로 맞추는 처리. 정수는 dtype 최대값으로 나눈다. |
| 다운샘플링 | 공간 표본 수를 줄이는 것. 현재 NumPy 인덱싱으로 32×32를 선택한다. 정교한 보간과 다르다. |
| 디코딩(Decoding) | JPEG 같은 압축 파일을 픽셀 배열로 읽는 과정. 손상 파일은 실패할 수 있다. |
| 이미지 평균 | 전체 픽셀·채널 값의 평균. 밝기·색상·배경의 영향을 함께 받는다. |
| 이미지 표준편차 | 전체 값의 퍼짐. 공간 배치를 잃으므로 무늬·질감을 직접 식별하지 못한다. |
| 이미지 상태 | ok, missing, not_sampled, corrupt, too_small을 구분한다. 미매칭 상품은 별도 상태다. |
| 문자열 길이 | Pandas 문자열의 문자 수. UTF-8 파일의 바이트 수와 같지 않다. |
| Word count / 단어 수 | 현재 공백으로 나눈 조각 수. 한국어 형태소·언어학적 단어 분석과 다르다. |
| Token / 토큰 | 텍스트 처리의 분할 단위. 이 미션의 공백 분할을 모든 NLP 토크나이저와 동일시하지 않는다. |

`Blue cotton shirt`의 길이는 17, 공백 기준 단어 수는 3이다. 누락 상품명은 계산할 때만 빈 문자열로 처리한다. 텍스트 원문은 보존한다. 배열 `[[0,0],[1,1]]`과 `[[0,1],[1,0]]`은 공간 배치가 달라도 평균·표준편차가 같으므로 두 통계만으로 패턴이 같다고 말할 수 없다.

SRC: [src/pipeline.py](../src/pipeline.py)의 `extract_text_features`, `extract_image_features`; [이미지 테스트](../tests/test_pipeline.py).

## 6. 정제와 결측 대치

| 용어 | 설명 |
| --- | --- |
| Validation / 유효성 검증 | 고객·날짜·금액 등의 조건을 확인하고 잘못된 행을 구분하는 과정. |
| Cleaning / 정제 | 오류·누락·범위 밖 입력을 명시한 규칙으로 처리한다. |
| 상호 배타적 제외 사유 | 행마다 첫 실패 사유 하나를 배정해 중복 집계를 막는다. |
| Audit / 감사 집계 | 각 단계의 입력·제외·출력 건수와 합계 기록. 원본 행 보관과는 구분한다. |
| Missing value / 결측 | 관측값이 없거나 계산 불가인 상태. 무조건 0 또는 평균으로 채우지 않는다. |
| Imputation / 대치 | 결측을 선택한 값으로 채우는 처리. 관측값의 복구를 보장하지 않는다. |
| 그룹 평균 대치 | 같은 카테고리의 관측 평균을 사용한다. 기존 관측값은 바꾸지 않는다. |
| Fallback / 대체 규칙 | 그룹 평균이 없을 때 대치 전 전체 평균을 사용하는 후속 규칙. |
| eligible mask | 실제 대치할 수 있는 행의 범위. 표본 미포함 이미지는 제외한다. |
| 분산 축소 | 여러 결측에 같은 평균을 넣으면 값들이 평균에 모여 퍼짐이 줄어드는 현상. |
| 선택 편향 | 관측·선택된 자료가 전체를 대표하지 않아 해석이 달라지는 문제. |
| MCAR/MAR/MNAR | 결측이 완전 무작위인지, 관측 변수로 설명되는지, 결측값 자체 등 미관측 요인과 관련되는지의 구분. 현재 데이터에서 원인을 입증한 것은 아니다. |

예시: 그룹 A에 10·30·결측이 있으면 20을 채운다. 그룹이 없는 관측값 50은 유지한다. 전체 관측이 10·30·50이면 그룹 평균을 구할 수 없는 결측은 전체 평균 30으로 채운다. 먼저 채운 20을 섞어 전체 평균을 다시 계산하지 않는다. 열 전체가 결측이면 그대로 남긴다.

분석용 피처 대치가 잘 동작해도 원본 금액·ID까지 같은 정책을 적용하면 의미가 바뀔 수 있다. 지정 열과 대치 전후 집계를 확인한다. 실제 분석에서는 결측 발생 원인과 관측 편향을 함께 검토해야 한다.

## 7. 통계·이상치·상관

| 용어 | 뜻과 해석 |
| --- | --- |
| Mean / 평균 | 합계÷개수. 큰 값의 영향을 많이 받을 수 있다. |
| Median / 중앙값 | 정렬한 자료의 가운데 위치 값. 평균과 함께 분포를 본다. |
| Quantile / 분위수 | 정렬한 자료의 특정 비율 위치를 요약한 값. 구현의 보간 규칙에 따라 달라질 수 있다. |
| Quartile / 사분위수 | Q1·Q2·Q3는 보통 25%·50%·75% 위치의 요약값이다. |
| Variance / 분산 | 평균에서 떨어진 정도의 제곱 요약. 단위가 원래 값의 제곱이다. |
| Standard deviation / 표준편차 | 분산의 제곱근. 원래 값과 같은 단위다. |
| ddof | 분산·표준편차 분모 보정. ddof=0은 N, ddof=1은 N−1을 사용한다. |
| 기술통계(Descriptive statistics) | 관측 자료의 중심·퍼짐·범위를 요약한다. 모집단 추정·인과 증명과 다르다. |
| Distribution / 분포 | 값들이 어느 범위에 얼마나 나타나는지의 모습. |
| 정규분포 | 종 모양의 대칭 분포 모형. 자료가 실제로 정규분포인지 별도 확인해야 한다. |
| 왜도·비대칭 | 한쪽 꼬리가 길거나 중심을 기준으로 대칭이 아닌 분포 특성. |
| Outlier / 이상치 | 선택한 기준에서 멀리 떨어진 값. 오류라는 뜻은 아니다. |
| IQR | Q3−Q1. 가운데 절반의 퍼짐을 나타낸다. |
| Fence / 경계 | Q1−k×IQR과 Q3+k×IQR. 현재 기본 k=1.5다. |
| Clipping / 보정 | 경계 밖 값을 경계로 제한. 제거와 다르고 분포·합계를 바꿀 수 있다. |
| Correlation / 상관 | 두 변수의 함께 변하는 관계. 선형·순위 등 방법별 의미가 다르다. |
| Pearson r | 선형 연관 계수. −1~1 범위이며 상수·표본 부족에서는 해석할 수 없다. |
| 완전 관측 쌍 | 두 값이 모두 유한하게 있는 행. 상관마다 유효 표본 수가 달라질 수 있다. |
| Causation / 인과 | 한 요인의 변화가 다른 결과를 변화시키는 관계. 상관만으로 증명되지 않는다. |
| 교란 요인 | 두 변수와 함께 관련되어 관계 해석을 흐릴 수 있는 요인. 계절성 등이 예다. |

평균은 `sum(x)/N`, 모집단 표준편차는 `sqrt(sum((x−mean)^2)/N)`이다. 이미지는 ddof=0을 사용하고, Pandas describe의 표준편차는 기본 표본 기준 ddof=1임을 구분한다.

IQR 예시 `[1,2,3,4,100]`은 Q1=2·Q3=4, 하한=−1·상한=7이므로 100만 탐지한다. `[-2,1,2,3,6]`의 하한−2·상한6과 같은 값은 정상 범위에 포함한다. IQR은 정규분포 가정이 필수는 아니며, 비대칭·여러 집단 혼합·IQR=0에서 판단력이 제한될 수 있다.

Pearson r은 공분산을 두 표준편차의 곱으로 나눈 값이다. r=0은 선형 연관이 없다는 요약이며 모든 비선형 관계가 없다는 뜻은 아니다. r이 커도 원인·캠페인 효과를 뜻하지 않는다. Pandas는 결측 쌍의 처리와 방법에 따라 계수를 계산하므로 유효 쌍 수를 함께 기록한다. [Pandas corr](https://pandas.pydata.org/docs/reference/api/pandas.DataFrame.corr.html)

SRC: [utils/analytics.py](../utils/analytics.py)의 `iqr_limits`, [utils/reporting.py](../utils/reporting.py)의 `pair_correlation`, `monthly_amount`, [파이프라인](../src/pipeline.py)의 `summarize`.

## 9. RFM·점수·세분화

| 용어 | 현재 정의와 주의점 |
| --- | --- |
| RFM | Recency·Frequency·Monetary로 구매 행동을 요약한다. |
| Recency | 기준일에서 마지막 유효 구매일까지의 일수. 작을수록 최근 구매다. |
| Frequency | H&M에서는 고유 구매일 수. 상품 행 수·주문 수와 다르다. |
| Monetary | 관찰 기간의 유효 구매금액 원값 합계. 이익·LTV·통화환산 금액이 아니다. |
| Reference date / 기준일 | 최근일수 계산 기준. 같은 범위의 표본을 비교할 때 유지한다. |
| Observation window | 관찰 기간. 기간 밖 행동을 관측한 것처럼 말하지 않는다. |
| Scoring / 점수화 | 지표를 규칙에 따라 점수로 바꾸는 것. 원값과 점수를 구분한다. |
| Rank / 순위 | 정렬한 위치. 같은 값의 처리 규칙이 결과에 영향을 준다. |
| Tie / 동점 | 같은 지표값. 현재는 평균 순위로 동일 점수를 준다. |
| qcut | 관측 분위수로 구간을 나누는 Pandas 함수. 중복 경계·동점 문제를 검토해야 하며 현재 RFM 구현에는 사용하지 않는다. |
| Segment / 세그먼트 | 규칙으로 나눈 고객 그룹. 이름 자체가 고객의 실제 상태를 증명하지 않는다. |
| Priority / 우선순위 | 여러 조건에 맞으면 먼저 일치한 그룹을 선택해 중복 분류를 막는다. |
| Profile / 프로파일 | 그룹별 고객 수·비중·대표 지표·금액 기여를 비교한 표. |
| VIP / Loyal | 높은 점수·반복 구매일에 근거한 관측 그룹 이름. 계약된 멤버십 등급이 아니다. |
| New | 최근성이 높고 기간 내 구매일이 하나인 그룹. 신규 가입일은 모른다. |
| Churned | 상대적으로 최근성이 낮은 그룹. 실제 이탈 확정·무응답 이유를 모른다. |
| Potential | 앞선 규칙에 맞지 않는 잔여 그룹. 실제 표본에서 비어 있을 수도 있다. |

가상 고객 A가 1월1일에 10·20, 1월3일에 30을 구매하고 B가 1월2일에 5를 구매했다면, 기준일 1월3일에서 A는 R=0·F=2·M=60, B는 R=1·F=1·M=5다. 전체 M은 65다. 같은 날 세 상품을 산 것을 세 번의 구매일로 세지 않는다.

점수는 `p=(평균 순위−0.5)/고객 수`를 계산해 p≤0.25면1, ≤0.50면2, ≤0.75면3, 나머지4로 정한다. R은 내림차순, F·M은 오름차순 순위를 사용한다. 동점이 많으면 각 점수나 그룹의 인원이 같지 않다. 인원 균등화를 위해 같은 값을 임의로 나누지 않는다. [Pandas rank](https://pandas.pydata.org/docs/reference/api/pandas.Series.rank.html)

SRC: [utils/analytics.py](../utils/analytics.py)의 `calculate_customer_rfm`, `segment_profile`; [RFM 테스트](../tests/test_analytics.py).

## 10. 사업 해석과 검증

| 용어 | 설명 |
| --- | --- |
| 근거·실행·검증 | 관측 숫자/차트 → 대상·행동·가설 → 반증 조건·추가 데이터의 연결. |
| KPI | 성과를 판단할 지표. 구매율·고객당 마진·수신 거부율 등을 목적에 맞게 정한다. |
| 전환율 | 특정 행동을 한 대상÷해당 행동을 할 기회가 있던 대상. 분모·기간을 명시한다. |
| 재구매율 | 정의한 이후 기간에 다시 구매한 비율. 구매일 빈도 그 자체와 다르다. |
| Retention / 유지율 | 다음 기간에도 남거나 활동하는 비율. 관측 기간의 성숙도를 고려한다. |
| 재활성화 | 일정 기간 활동이 없던 고객의 다시 구매·활동을 유도하는 것. |
| Margin / 마진 | 수익에서 관련 원가를 뺀 금액. 구매금액만으로 알 수 없다. |
| ROI | 투자 대비 순이익 등 정의한 수익성 지표. 비용·효과 정보 없이 확정할 수 없다. |
| CAC | 고객 획득 비용. 현재 데이터에 없어 기존 고객 유지 비용과 배수를 비교하지 않는다. |
| LTV/CLV | 고객 관계 전체 또는 명시한 기간의 가치 추정. 관측 세 달의 구매금액과 다르다. |
| AOV / 객단가 | 보통 주문당 구매금액. 현재 Monetary/Frequency는 구매일당 금액이지 주문당 금액이 아니다. |
| A/B test / 대조 실험 | 무작위 발송군·미발송군 등의 성과를 비교해 순증 효과를 추정한다. |
| 자연 재구매·할인 잠식 | 혜택 없이도 살 고객에게 할인해 비용만 늘어나는 위험. |
| Seasonality / 계절성 | 달·계절 등에 따른 반복 변화. 의류 구매의 시간 효과를 고려한다. |

금액 비중이 큰 그룹을 찾는 것과 그 그룹에 특정 캠페인이 가장 수익성 있다는 것은 다른 주장이다. 연락 동의·비용·마진·재고·반응·향후 거래가 필요하다. 대조군과 이후 기간의 순증 성과를 확인한다. 현재 인사이트 생성 SRC는 [utils/reporting.py](../utils/reporting.py)의 `write_insights`다.

## 11. 표본·대용량 데이터·공개 범위

| 용어 | 의미 |
| --- | --- |
| Sampling / 표본 추출 | 전체에서 일부를 선택한다. 현재는 선택 고객의 기간 내 유효 거래를 모두 보존한다. |
| Seed / 시드 | 난수 생성의 시작 조건. 같은 입력 순서·규칙·환경과 함께 재현성에 기여한다. |

## 13. 테스트·재현·Git 작업 흐름

| 용어 | 뜻과 적용 |
| --- | --- |
| 단위·회귀 테스트 | 작은 기대값과 수정 후 기존 동작 보존을 확인한다. 같은 구현을 복사한 테스트는 피한다. |

| Reproducibility / 재현성 | 같은 입력·설정·환경에서 같은 결과를 얻는 성질. 시드 하나만으로 보장되지 않는다. |
| Harness / 검증 실행 도구 | 테스트·새 커널 실행을 일정한 명령으로 연결한 도구. 별도 거대한 자동화 체계가 필요하지 않다. |
| 구현·검증 루프 | 작은 작업 → 검증 → 실패 원인 수정 → 성공 근거 기록의 반복. |
| Repository / 저장소 | Git이 추적하는 프로젝트와 이력. 로컬과 원격은 별개다. |
| Clone / 복제 | 원격 또는 다른 저장소의 추적 파일·이력을 받아 작업 공간을 만든다. |
| Commit / 커밋 | 한 변경의 스냅샷과 설명. 왜 바꿨는지·검증을 간결하게 남긴다. |
| Branch / 브랜치 | 특정 이력 위에서 작업하는 이름. 특별한 파일 복제 방식이 아니라 커밋 참조다. |
| main / develop / feature | 검증 기준 상태 / 기능 통합 상태 / 개별 작업 공간으로 역할을 정할 수 있다. develop은 필수가 아니다. |
| Issue / 이슈 | 목적·완료 조건·진행·결정·남은 작업의 기록. 커밋 링크를 모아 볼 수 있다. |
| PR / Pull Request | 브랜치의 미반영 변경을 설명·검토·병합하는 제안. 혼자 작업해도 유용하다. |
| Merge / 병합 | 서로 다른 이력을 통합한다. 충돌 해결과 검증이 필요할 수 있다. |
| Conflict / 충돌 | 같은 부분에 양립하기 어려운 변경이 있을 때 해결해야 하는 상태. |
| Push / Fetch | 로컬 이력을 원격에 게시 / 원격 이력을 로컬 참조로 가져온다. |
| Refs #번호 | 커밋·PR에서 관련 이슈를 참조하는 기록. 자동 종료 의도와 구분한다. |
| Closes/Fixes | 기본 브랜치에 반영될 때 이슈를 자동 종료할 수 있는 키워드. 미완료 이슈에 남용하지 않는다. |
| Amend | 마지막 커밋을 다시 만드는 것. 공유된 이력을 참조 추가만을 위해 수정할 필요는 없다. |
| .gitignore | 로컬 데이터·환경·임시 파일의 추적 제외 규칙. 이미 추적 중인 파일은 자동 해제되지 않는다. |
| 상대 경로 | 문서 위치 기준 파일 경로. 다른 PC나 GitHub에서도 연결되게 한다. |

## 14. 선택 보너스·예측 확장 용어

| 용어 | 뜻·적용 범위 |
| --- | --- |
| 이미지 히스토그램 피처 | 픽셀 값 구간별 개수·비율. 현재 필수 mean/std와 구분하는 선택 확장이다. |
| Edge / 엣지 | 공간적으로 값이 급변하는 경계. NumPy 차분·주변 연산으로 확장할 수 있다. |
| Cohort / 코호트 | 가입월 등 같은 출발 조건의 집단. 첫 관측 구매월을 가입월이라고 부르지 않는다. |
| Cohort retention | 집단의 이후 기간 활동 비율. 아직 도래하지 않은 기간을 0으로 세지 않는다. |
| Interactive visualization | 확대·선택·툴팁 등 조작 가능한 차트. Plotly는 이 보너스에 한해 허용된다. |
| Target / 타겟 | 예측하려는 결과. T 이후 30일 구매 여부·금액 등이 후보이며 현재 학습은 미구현이다. |
| Label / 레이블 | 학습 사례의 실제 타겟 값. 관찰이 충분히 끝난 사례에 정의한다. |
| Feature leakage / 정보 누수 | 예측 시점에 알 수 없는 미래 정보를 피처·대치·선정에 사용한 문제. |
| Train/validation/test | 학습·설정 선택·최종 성능 확인의 자료 구분. 시간 자료는 미래가 과거로 섞이지 않게 한다. |
| Cold start | 과거 기록이 적거나 없는 고객·상품의 예측 문제. RFM을 만들 수 없는 경우를 별도로 설계한다. |
| 관측 중도절단 | 향후 기간이 끝까지 관측되지 않아 결과를 모르는 상태. 구매 없음과 구분한다. |

현재 예측 확장은 설명·설계 과제다. 기준시점 T까지의 데이터로만 피처를 만들고, 이후 관측이 끝난 기간의 타겟으로 검증해야 한다. 미래 금액을 그대로 피처에 넣거나 관측되지 않은 고객을 이탈로 라벨링하면 안 된다.
