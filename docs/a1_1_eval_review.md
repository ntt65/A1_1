# 평가 자료 대조와 준비 의견

검토일: 2026-11-07. 원본은 [평가 PDF](a1_1_eval.pdf), 대조본은 [평가 Markdown](a1_1_eval.md)이다. 두 원본 파일은 수정하지 않았다. 관련 작업은 GitHub 이슈 #6이다.

## 확인한 내용

PDF는 17페이지이며 세부 평가 문항은 15~17페이지에 걸쳐 있다. Markdown의 `5. 평가문항`은 필수 19개(항목1 8개, 항목2 4개, 항목3 4개, 항목4 3개)와 선택 보너스 항목을 담고 있다. 현재 로컬과 원격에서 확인한 Markdown은 414줄이며 미션 설명·참고 코드·참고 인사이트·평가 문항으로 구성된다.

현재 저장된 파일에서 Gemini의 별도 답변으로 구분되는 문단은 찾지 못했다. 참고 예시에는 메서드의 `pass`와 가상의 세그먼트 숫자·인사이트가 있다. 이를 우리 구현에 대한 완성 답변으로 판정하지 않았다. 편집기의 미저장 내용이나 다른 파일·브랜치의 답변은 이번 검토 범위에 포함되지 않는다.

PDF 15페이지에는 다른 프로젝트 URL이, 17페이지에는 FAIL과 재구현 불가라는 화면 문구가 보인다. 이 화면을 현재 `ntt65/A1_1`의 평가 결과로 해석하지 않는다. 실제 현재 평가는 별도로 받아야 한다.

## 자료에 대한 의견

| 확인 사항 | 준비할 내용 |
| --- | --- |
| 참고 클래스는 인터페이스 예시 | `pass` 대신 실제 클래스 호출과 결과를 보여준다. SRC: `src/pipeline.py` |
| 미션 설명이 Markdown에 반복됨 | 요구사항의 수가 두 배라는 뜻이 아니다. 평가 문항 19개를 기준으로 증거를 연결한다. |
| 참고 인사이트의 통화·효과 수치 | 예시 금액이나 재구매율 상승을 실제 관측값처럼 말하지 않는다. 현재 원본 금액의 통화를 추정하지 않는다. |
| 제출 URL·브랜치 항목 | 평가할 실제 저장소와 최종 병합된 `main`을 안내한다. 원본 PDF에 적힌 다른 프로젝트 URL을 복사하지 않는다. |
| 구현 여부와 이해 여부가 함께 평가됨 | 파일 존재만 보이지 말고 수식·선택 이유·작은 입력·실제 실행 근거·한계를 설명한다. |
| 재구현 가능성 | 대치 20/30/50, IQR 경계, RFM 0·2·60/1·1·5를 직접 재현하고 코드 흐름을 설명한다. |

## 준비 계획

1. [Q&A 문서](a1_1_evaluation_qa.md)의 19개 질문에 각각 30~60초로 답한다.
2. 각 답변에서 지정한 SRC를 열어 계산 부분을 짚는다. 외운 일반론과 현재 구현의 차이를 확인한다.
3. 실제 노트북의 NB_LOAD~NB_REPRO를 새 커널로 실행하고 검증 JSON과 대조한다.
4. 분산 축소·분포 왜도·동점·이미지 메모리·미래 정보 누수의 꼬리 질문을 연습한다.
5. 제한된 데이터 접근을 고려해 공개 가능한 README와 비공개 실제 실행본을 구분해 준비한다.
6. 모르는 용어는 [기술 학습서](tech_study.md)에서 정의와 작은 예제로 복습한다.

## 준비 완료 기준

- 19개 질문마다 코드 위치와 확인할 결과가 있다.
- 데이터 단위(거래·상품·고객·월)를 혼동하지 않는다.
- 점수 동점·구매일 빈도·원본 금액 보존을 설명한다.
- 벡터화가 모든 Python 반복을 제거하거나 항상 SIMD·특정 속도 배수를 보장한다고 말하지 않는다.
- 캠페인 효과·실제 이탈·신규 가입·LTV를 현재 관측만으로 확정하지 않는다.
- 선택 보너스와 필수 구현을 구분한다. 보너스는 현재 구현 완료로 주장하지 않는다.

이 문서는 자료 검토와 준비 계획이며, 평가자의 PASS 판정을 대신하지 않는다.
