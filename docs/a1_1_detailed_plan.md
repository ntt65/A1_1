## 재사용과 반복 작업의 운영 기준

상태를 관리하는 분석 API는 `DataAnalyzer`, 공통 이미지 처리와 검증 실행 도구는 `utils/`, 설정·분석 호출·해석은 노트북에 둔다. 코드 작성 시 입력·출력·부작용 독스트링과 처리 이유 주석을 함께 작성하고 검증 후 바뀐 부분만 수정한다.

별도 에이전트 자동화 체계를 추가하지 않고 [AGENTS.md](../AGENTS.md)의 작은 구현·검증 반복을 적용한다. 가상 입력 검증은 `python -m utils.run_checks`, 실제 입력 또는 노트북 변경 시 검증은 같은 명령의 `--with-sample`로 수행한다. 성공한 단계만 체크표와 작업별 커밋에 기록한다.

탐색 비용을 줄이기 위해 [index.md](../index.md)에서 파일을 찾고 [reverse_index.md](../reverse_index.md)에서 변경 영향을 확인한 뒤 관련 함수와 현재 계획 구간만 읽는다. 큰 데이터·실행 출력·환경 폴더의 반복 읽기를 피하고, 완료 상태를 별도 계획 파일에 중복 작성하지 않는다. 파일 구조를 바꾸면 두 인덱스를 함께 갱신한다. 실제 결과는 Git에서 제외된 `data/processed/`에 두고 필요할 때만 확인한다. 토큰 절약량은 별도 측정 없이 수치로 주장하지 않는다.

## P0. 시작 전 실행 환경 확인

새 환경에서는 Python 3.8 이상과 분석 패키지의 호환성을 확인한다. 현재 검증한 실행 환경은 Python 3.11 가상환경이며 버전과 검증 결과는 체크표 P0에 기록되어 있다. Windows에서 같은 환경을 만들 때는 저장소 루트에서 `py -3.11 -m venv .venv`를 실행하고 `.venv\Scripts\python.exe`로 `requirements.txt`를 설치한다. 노트북 실행 도구는 별도로 설치한다. 네 분석 패키지의 import와 노트북 커널의 `sys.executable`이 같은 `.venv`를 가리키는지 확인한다. Jupyter가 사용자 설정 폴더에 쓸 수 없는 환경에서는 `JUPYTER_CONFIG_DIR`과 `JUPYTER_RUNTIME_DIR`을 `.venv` 아래의 쓰기 가능한 폴더로 지정한다.

## A. 데이터 선정과 검증

### A1. 데이터 접근과 공개 범위 확인

H&M 대회 자료는 구매 내역 `transactions_train.csv`, 상품 정보 `articles.csv`, 상품 ID로 찾는 이미지를 제공한다. 원본 규모는 전체 약 34.6 GB, 거래 CSV 약 3.49 GB이며, 이 프로젝트의 로컬 입력은 Kaggle에서 선별한 표본이다. [H&M 데이터 설명](https://www.kaggle.com/competitions/h-and-m-personalized-fashion-recommendations/data?select=transactions_train.csv)

1. A 단계의 첫 2시간에 미션 제공 샘플의 유무와 재사용 조건을 확인한다. 제공 샘플이 A2~A4를 충족할 수 있으면 우선 검토한다. 그 외에는 계정 소유자가 H&M 대회 규정에 동의한 뒤, 비공개 Kaggle Notebook의 **Add Input**에서 해당 대회 데이터를 연결할 수 있는지 확인한다. 노트북 입력 화면에서 실제 원본 경로를 확인한다. [Kaggle Notebook 문서](https://www.kaggle.com/docs/notebooks)
2. [표본 추출 노트북](../notebooks/prepare_hm_sample.ipynb)을 비공개 Kaggle Notebook으로 가져온다. A3에 따라 구매 행과 상품 이미지를 선별하고 `/kaggle/working/hm_sample.zip`에 저장한다. 다운로드 전에 파일 목록과 압축·해제 용량을 확인하고, 규정상 허용되는 표본 결과 파일만 로컬 `data/raw/hm/`에 받는다. 전체 대회 묶음, 거래 원본 CSV, 전체 이미지 폴더는 Kaggle 입력으로만 사용한다. 공식 CLI의 `download -f`는 파일 전체를 받는 방식이므로 거래 행 표본 추출에 사용하지 않는다. [Kaggle 파일 다운로드](https://github.com/Kaggle/kaggle-cli/blob/main/docs/competitions.md#kaggle-competitions-download) · [노트북 결과 다운로드](https://github.com/Kaggle/kaggle-cli/blob/main/docs/kernels.md#kaggle-kernels-output)
3. `.gitignore`에 `/data/`가 적용되어 있다. 내려받기 전에 `git check-ignore data/raw/hm/hm_sample.zip`과 `git ls-files -- data`로 제외 여부와 추적 파일이 없음을 확인한다. 표본 ZIP과 압축을 푼 파일, 중간 결과는 `data/`에 둔다.
4. 대회 규정을 기준으로 비공개 표본의 로컬 사용 범위와 GitHub에 올릴 코드·집계 표·차트·README 수치의 공개 범위를 구분해 기록한다. GitHub에 실행된 집계 결과를 제출할 수 있는 조건까지 확인되어야 최종 채택한다. [H&M 대회 규정 7·8절](https://www.kaggle.com/c/h-and-m-personalized-fashion-recommendations/rules)

접근·용량·공개 범위 문제로 H&M을 제출에 사용할 수 없으면 원인을 기록하고 대체 데이터를 검토한다. CC BY 4.0으로 제공되는 UCI Online Retail 거래와 Amazon Berkeley Objects 상품·이미지를 사용하는 경우, 두 데이터 흐름을 분리하는 구성이 평가 기준에 허용되는지 먼저 확인한다. 서로 다른 상품 ID는 연결하지 않는다. UCI의 `InvoiceNo`는 주문 ID로, `UnitPrice × Quantity`는 금액으로 사용하고 취소·반품을 양의 구매 집계와 분리한다. 원본 엑셀은 CSV로 내보낸다. ABO 상품은 자체 ID로 메타데이터와 이미지를 연결한다. [UCI Online Retail](https://archive.ics.uci.edu/dataset/352/online+retail) · [Amazon Berkeley Objects](https://amazon-berkeley-objects.s3.us-east-1.amazonaws.com/index.html)

이 PC의 표본 복원은 완료되어 있다. 다른 작업 환경에서는 [README](../README.md#hm-표본-준비)의 복원 절차를 실행하고, 로컬 `data/drive_source.json`과 `data/raw/hm/sample_manifest.json`으로 원본 연결과 추출 설정을 확인한다.

### A2. 입력 구조 고정

H&M 채택 시 표본 ZIP에 아래 파일을 담는다. 첫 샘플을 읽어 실제 파일명과 열 이름을 대조한 뒤 README에 확정값을 기록한다.

| 입력 | 로컬 경로 | 분석용 열과 단위 |
| --- | --- | --- |
| 구매 내역 | `data/raw/hm/transactions_sample.csv` | 선택 고객의 유효 구매 상품 행. `customer_id`, `article_id`, `order_date` (`t_dat`), `amount` (`price`), `sales_channel_id` |
| 상품 목록 | `data/raw/hm/articles_sample.csv` | 표본 거래의 `article_id`별 한 행. `product_name` (`prod_name`), `category` (`product_type_name`), 원본 이미지 유무 및 표본 포함 여부 |
| 이미지 | `data/raw/hm/images/` | 거래에 등장한 상품 중 선별한 JPG. 파일이 없는 상품과 표본에서 뺀 상품을 구분 |
| 추출 기록 | `data/raw/hm/sample_manifest.json` | 출처, 기간·채널·시드, 표본 추출 전 기준일, 거래 제외 집계, 이미지 상태별 건수 |

고객·상품·주문 ID는 문자열로 유지하고 공백만 있는 ID는 결측으로 처리한다. 날짜는 원본 형식을 지정해 달력일로 변환하고, 금액은 유한한 수로 변환한다. H&M은 `sales_channel_id`의 의미를 출처에서 확인한 후 온라인 구매를 분석 대상으로 삼는다. 온라인 채널을 확인할 수 없으면 전체 채널을 사용하고 결과 범위를 전체 채널로 표시한다. 분석용 거래 테이블에는 위 거래 열 5개, 상품명과 카테고리, 이미지 처리 상태가 들어가도록 한다. 이미지 배열은 상품 단위 배치에서 처리하고, 계산한 피처를 상품 ID로 연결한다.

### A3. 관찰 기간과 표본 고정

1. 거래 범위에서 완전한 달 3개 이상을 연속으로 선택한다. 양끝 달의 수집 범위가 확인되지 않으면 제외한다. 시작일 포함, 종료일 제외 규칙을 적용하고 선택한 기간을 기록한다.
2. Kaggle Notebook에서 `transactions_train.csv`의 필요한 열만 Pandas `usecols`와 `chunksize`로 읽는다. 첫 순회에서 기간·채널·유효성 조건을 만족하는 고객 ID와 마지막 거래일을 수집한다. 정렬한 고객 ID에서 시드 `42`로 처음에는 최대 1,000명을 선택하고, 두 번째 순회에서 선택 고객의 기간 내 유효 거래를 모두 추출해 청크별로 저장한다. 유효 거래 1,000건 또는 세그먼트 4개를 확보하기 어려우면 표본 규모나 기간을 늘려 다시 검증한다.
3. 선택 거래에 포함된 상품의 메타데이터만 내보내고, 해당 상품 중 실제 파일이 있는 이미지에서 처음에는 최대 200장을 고정 시드로 선별한다. 이미지 표본 선정은 RFM 고객·거래 표본과 분리한다. 파일 없음과 표본 미포함은 추출 단계에서, 읽기 성공과 손상은 이미지 처리 단계에서 구분한다. 고객 메타데이터 `customers.csv`는 RFM 집계에 쓰이지 않는다.

### A4. 실데이터 채택 판정

정제 후 유효 거래 1,000건 이상, 분석용 테이블 8개 이상 열, 수치·범주·날짜 등 최소 3가지 유형을 확인한다. 실제 상품명과 이미지 배열이 상품 ID 기준으로 연결되는지 확인하고, 이미지 산점도와 상관계수에 사용할 서로 다른 관측값이 있는지도 점검한다. 초기 결과에 원본 기간, 최종 기간, 고객 수, 거래 수, 상품 수, 조인 일치율과 이미지 읽기 성공률을 남긴다. 구매 금액의 화폐 단위가 확인되지 않으면 원본 단위로 보고한다.

## B. 로드와 멀티모달 피처

### B1. `DataAnalyzer` 입출력 연결

`src/pipeline.py`의 `DataAnalyzer`에 로드·결측치 대치·IQR 탐지·RFM 계산 메서드를 유지하고 대치 전략, 대상 열, IQR 배수와 기준일을 인자로 받는다. 실제 분석에 필요한 열과 ID 자료형을 명시하고, 필수 열이 빠졌거나 입력이 비었으면 경로 또는 누락 열을 오류에 표시한다. `--data`는 CSV 로드 확인에 사용한다. 노트북은 클래스 메서드를 호출해 분석을 진행한다. 관찰 기간, 시드, 데이터 경로 등 실험 설정은 저장소 기준 상대 경로를 사용하는 설정 셀 한 곳에 둔다.

### B2. 상품 조인과 분석 단위 분리

거래에서 상품으로 `article_id` 기준 다대일 왼쪽 조인을 한다. 상품 목록의 비어 있는 키는 조인 대상에서 제외하고, 중복 키는 원인을 확인한 뒤 처리 규칙을 기록한다. 미매칭 거래는 별도로 집계한다. 조인 전후 거래 행 수는 정확히 비교하고 금액 합계는 문서화한 부동소수점 허용 오차로 대조한다. 구매와 월별 추세는 거래 단위, 이미지·텍스트 관계는 상품 단위, RFM은 고객 단위에서 계산한다.

### B3. 이미지 피처 연결

상품 ID별 이미지를 `matplotlib.image.imread()`로 한 번 읽는다. 회색조는 RGB 세 채널로 펼치고, 알파 채널이 있으면 RGB 세 채널을 사용한다. 정수 픽셀은 자료형의 최대값으로 나눠 0~1 범위로 맞추고, 이미 0~1인 실수 픽셀은 원래 값을 사용한다. NumPy 인덱싱으로 기본 `32 × 32 × 3` 크기로 다운샘플링한다. 누락·손상·최소 크기 미달 이미지는 건수를 기록하고 피처를 결측으로 둔다. 읽기 성공 이미지를 같은 모양의 배치로 쌓아 기존 `extract_image_features()`의 축 연산으로 이미지당 평균과 표준편차를 계산한다. 산출된 두 피처를 상품별 새 열로 연결한다. 메모리가 부족하면 배치 크기를 줄인다.

### B4. 텍스트 피처와 입력 검증

`extract_text_features()`로 상품명 길이와 공백 기준 단어 수를 구한다. 누락 상품명을 빈 문자열로 처리하기 전에 원래 결측 수를 기록한다. 작은 입력에서 `"Blue cotton shirt"`의 길이 17과 단어 수 3을 확인한다. 픽셀 값의 절반이 0이고 절반이 1인 배열에서 이미지 평균과 표준편차가 각각 0.5인지 확인하고, 회색조·RGB·읽기 실패 이미지도 검증한다.

## C. 정제와 RFM 집계

### C1. 유효 거래 분리

대표 제외 사유는 고객 ID 누락 → 날짜 오류 → 주문 모드의 주문 ID 누락·취소 → 비유한·변환 불가·0 이하 금액 순으로 기록한다. 정제에서 유효한 거래 중 분석 기간·채널 밖 거래와 표본 미선택 거래는 별도로 센다. H&M은 Kaggle에서 `원본 행 수 = 정제 제외 + 범위 제외 + 표본 제외 + 표본에 남긴 거래`를 확인해 추출 기록에 남긴다. 로컬에서는 CSV 행 수와 추출 기록을 대조하고, 분석 입력의 유효성을 재검증한다. 동일 값의 H&M 구매 행은 유지한다. 상품·이미지 미매칭은 구매 유효성 판정과 분리하고, RFM과 월별 추세는 같은 유효 구매금액 원값을 사용한다. 유효 거래가 비면 집계를 중단하고 사유를 표시한다.

### C2. 그룹별 결측치 대치

`handle_missing_values()`의 그룹 평균을 지정한 수치 피처에만 적용한다. 예를 들어 분석용 이미지 평균 사본에 카테고리별 평균을 적용하고, 그룹 평균이 없으면 해당 피처의 전체 평균을 사용한다. 표본에 포함되지 않은 이미지의 값은 대치 대상에서 제외한다. 전체가 결측인 피처는 결측으로 두고 보고한다. 원본 이미지 피처와 기존 관측값은 보존한다. 대치 전후 결측 수와 카테고리 평균·전체 평균이 각각 채운 건수를 확인한다. 실제 결측이 없으면 별도 시연용 사본에 표시한 결측을 만들어 대치 결과를 보여주고, 본 분석에서는 관측값을 사용한다.

작은 입력에서 A 카테고리의 `[10, 30, 결측]`은 `20`으로 채우고, 카테고리 누락 행의 관측값 `50`은 유지한다. 이 세 관측값만 있을 때 그룹 평균이 없는 행의 결측은 전체 평균 `30`으로 채워지는지 확인한다.

### C3. IQR 탐지와 분포 보정

`detect_outliers()`에서 유효한 수치로 Q1과 Q3를 구하고, `IQR = Q3 − Q1`, 기본 임계 배수 `1.5`로 하한과 상한을 계산한다. 경계와 같은 값은 정상 범위에 포함한다. EDA용 사본의 값만 상하한으로 보정해 원본과 비교한다. `[1, 2, 3, 4, 100]`에서 경계는 `−1`, `7`이고 `100`만 탐지된다. `[−2, 1, 2, 3, 6]`에서는 양쪽 경계값이 탐지되지 않아야 한다. 금액에서 이상치가 0건이거나 IQR이 0이면 그 결과를 기록한다. 전후 비교가 가능한 다른 수치 변수가 있으면 해당 변수로 박스플롯을 작성한다.

### C4. RFM 지표와 점수 산출

| 지표 | 집계 규칙 |
| --- | --- |
| `Recency` | A3에서 정한 기준일과 고객 최종 구매일의 달력일 차이. 기준일 구매는 0일 |
| `Frequency` | H&M은 고객별 고유 구매일 수. 주문 ID가 있는 입력에서는 고유 주문 수 |
| `Monetary` | 고객별 유효 구매금액 원값의 합계 |

기준일은 기간·채널 내 마지막 유효 거래일로 정하고 같은 범위에서 표본 크기를 바꿀 때도 유지한다. 기준일이 입력 거래의 최종일보다 앞서면 오류를 표시한다. R은 Recency 내림차순, F와 M은 각 지표 오름차순으로 평균 순위를 매긴다. 고객 수를 `n`이라 할 때 `(평균 순위 − 0.5) / n`을 계산한다. 이 값이 0.25 이하이면 1점, 0.50 이하이면 2점, 0.75 이하이면 3점, 그보다 크면 4점이다. 동일값은 같은 점수를 받고, 데이터가 한 값에 몰려 일부 점수가 비면 그 분포를 기록한다. 행 순서를 바꿔도 동일 고객의 지표와 점수가 같은지 확인한다.

집계 검증용으로 A 고객이 1월 1일에 `10`, `20`, 1월 3일에 `30`을 구매하고 B 고객이 1월 2일에 `5`를 구매한 입력을 사용한다. 1월 3일을 기준으로 A의 R·F·M은 `0·2·60`, B는 `1·1·5`다. 전체 고객의 Monetary 합계는 `65`다. 주문 모드에서는 같은 주문의 상품 행 여러 개가 한 주문으로 집계되는 경우도 확인한다.

### C5. 고객 세그먼트 분류

아래는 실데이터 검토 전의 초기 규칙이다. 위에서부터 처음 일치한 그룹에 배정한다. `R`, `F`, `M`은 점수이며 구매 횟수는 C4에서 정한 Frequency 원값이다.

| 우선순위 | 그룹 | 초기 조건 |
| --- | --- | --- |
| 1 | `VIP` | R·F·M이 모두 3점 이상이고 구매 횟수 2회 이상 |
| 2 | `Loyal` | R·F가 3점 이상이고 구매 횟수 2회 이상 |
| 3 | `New` | R이 3점 이상이고 관찰 기간 내 구매 횟수 1회 |
| 4 | `Churned` | R이 2점 이하인 이탈 위험 고객 |
| 5 | `Potential` | 위 조건에 해당하지 않는 고객 |

전체 유효 고객이 한 그룹에만 속하고, 고객이 있는 그룹이 최소 4개인지 확인한다. 부족하면 먼저 점수별 고객 수와 최초 분류표를 저장하고, 관찰 기간이나 표본 규모를 넓혀 다시 확인한다. 낮은 최근성 그룹에 과거 반복 구매 고객과 1회 구매 고객이 모두 있다면, 재활성화 전략의 차이를 근거로 해당 그룹을 두 그룹으로 나누는 규칙을 검토한다. 규칙 변경 시 이전·이후의 고객 수와 금액 비중을 남긴다. 미션 기준인 4개 그룹을 충족할 때까지 C5를 미완료로 둔다. `New`는 기간 내에 한 번 구매가 관측된 고객이며, `Churned`는 낮은 최근성을 기준으로 분류한다.

Frequency와 Monetary의 관계를 해석할 때 두 지표가 모두 같은 구매 기록에서 집계된다는 점을 고려한다. 탐색과 주요 통계 해석마다 **관측 수치 하나 이상과 시사점 한 문장 이상**을 붙인다.

### F2. 공개 범위와 라이브러리 점검

분석 구현은 표준 라이브러리와 NumPy·Pandas·Matplotlib·Seaborn을 사용한다. 이미지 입력은 허용된 `imread()`로 읽고 NumPy로 변환·계산한다. OpenCV·Pillow를 분석 코드에서 직접 사용하거나 Scikit-learn·NLTK·자동 EDA 패키지를 도입하지 않는다. Plotly는 인터랙티브 시각화 보너스를 선택했을 때 사용한다. Git 변경 사항과 노트북 출력에 원본 이미지, 원본 거래 행, 고객 ID, 인증 정보, 개인 환경에 종속되는 경로가 포함되는지 확인하고 공개 범위에 맞게 정리한다. 집계 표와 차트 역시 확인한 이용 조건에 맞춰 저장한다.

## QA 답변 준비

답변은 **핵심 원리 → 코드·수식 → 저장된 실행 결과 → 한계와 적용 범위** 순서로 준비한다. 실제 구현과 결과가 확인된 부분을 완료형으로 설명한다. 아래 내용은 구현 후 코드와 증거를 붙일 답변 기준이다.

### Q1. 메서드별 책임을 어떻게 나누는가

`load_data()`는 입력과 자료형 확인, 피처 메서드는 상품 단위 수치화, `handle_missing_values()`는 지정한 열의 결측 처리, `detect_outliers()`는 IQR 마스크, `calculate_rfm()`는 고객 단위 집계를 담당한다. 노트북은 이 메서드의 실행 순서와 결과 해석을 보여준다.

`self.df`를 수정하는 메서드는 다음 단계에 영향을 줄 수 있다. 각 단계의 입력·출력과 변경 열을 설명하고, 원본 거래금액과 분석용 보정 사본이 구분되는 것을 실행 결과로 보인다.

### Q2. 파라미터화가 어떤 이점을 주는가

대치 대상 열·그룹·전략, IQR 배수, RFM 기준일과 Frequency 단위를 외부에서 지정해 데이터셋별 의미를 반영한다. RFM 기준일·Frequency 단위·주문 열을 인자로 받으며, 기준일이 최종 구매일보다 앞서면 오류를 표시한다. 기준일 변경, 다른 컬럼명, 구매일 모드와 주문 모드의 차이를 작은 입력으로 시연한다. UCI에 적용할 때는 주문 ID와 `UnitPrice × Quantity`를 준비하는 과정도 설명한다.

### Q3. 배열 축 연산과 메모리·SIMD를 어떻게 설명하는가

이미지를 `(N, H, W, C)` 배치로 모으고 `axis=(1, 2, 3)`으로 평균·표준편차를 계산해 이미지당 값 하나씩을 얻는다. 파일 읽기와 배치 순회 과정, 픽셀 통계를 계산하는 배열 연산을 각각 코드에서 짚는다. Python의 픽셀별 반복 호출을 줄이고 동일 자료형 배열에 대한 NumPy 내부 연산을 사용하는 이유를 설명한다.

배열의 `strides`와 연속성은 슬라이싱에 따라 달라질 수 있다. 실제 배치의 `shape`, `dtype`, `strides`, `flags`, `nbytes`를 확인한다. SIMD는 NumPy 빌드와 CPU, 연산 구현에 따라 선택되는 최적화다. 속도 배수를 제시하려면 같은 입력과 결과 정확도를 사용한 별도 검증 셀에서 측정값을 남긴다. [NumPy strides](https://numpy.org/doc/stable/reference/generated/numpy.ndarray.strides.html) · [NumPy SIMD](https://numpy.org/doc/stable/reference/simd/index.html)

### Q4. 이미지 평균과 표준편차는 무엇을 나타내는가

평균은 정규화한 픽셀 수준의 요약이고 표준편차는 픽셀 값의 퍼짐이다. 밝기·색상·배경의 영향을 함께 받으므로 상품과 촬영 조건을 고려해 해석한다. 예를 들어 `[[0, 0], [1, 1]]`과 `[[0, 1], [1, 0]]`은 공간 배치가 달라도 같은 평균과 표준편차를 갖는다. 상품 패턴이나 질감에 대한 주장은 추가 피처와 검증이 있을 때 제시한다.

이 문항은 미션의 이미지 수치화 학습 목표에 대응한다. B4의 알려진 입력 검증과 `NB_FEATURES`를 증거로 사용한다.

### Q5. 그룹 대치가 필요한 이유와 위험은 무엇인가

그룹별 분포 차이를 반영하려는 목적과 대치 대상 피처를 선택한 이유를 설명한다. 그룹 평균·전체 평균의 적용 건수, 대치 전후 결측 수와 분산 변화를 보인다. 그룹 누락·그룹 전체 결측·피처 전체 결측의 처리 기준과 관측값 보존을 C2의 검증으로 설명한다. 대치된 이미지 통계와 직접 관측한 이미지 통계는 출처를 구분하고, 상관계수 해석은 관측값을 기준으로 한다.

### Q6. IQR의 효과와 한계를 어떻게 설명하는가

`IQR = Q3 − Q1`과 상하한 수식을 코드에서 짚고, 경계와 같은 값은 정상 범위에 포함되는 것을 보인다. 왜도가 크거나 여러 상품군이 섞인 분포에서는 유효한 고액 구매도 탐지될 수 있다. IQR 표시를 근거로 거래 오류를 확정하지 않으며, EDA용 보정과 원본 금액으로 계산한 RFM 합계를 함께 제시한다.

### Q7. RFM 점수와 세분화의 타당성을 어떻게 검증하는가

C4의 기준일·Frequency 단위·평균 순위 점수와 C5의 조건 우선순위를 설명한다. `rank(method="first")`로 동점을 쪼개던 기존 방식은 평균 순위로 수정했다. 같은 지표값의 점수가 같고 입력 순서를 바꿔도 유지되는지 회귀 검증한다. [Pandas 순위 계산](https://pandas.pydata.org/docs/reference/api/pandas.Series.rank.html)

실제 그룹별 최근일수·구매 빈도·구매금액·고객 수를 비교하고 규칙 변경의 전후 근거를 남긴다. `New`는 기간 내 한 번 구매가 관측된 그룹이고, `Churned`는 상대적으로 최근성이 낮은 이탈 위험 그룹으로 설명한다. 그룹명만으로 고객의 실제 가입 시점이나 이탈 여부를 단정하지 않는다.

### Q8. 어떤 캠페인을 먼저 실행할 것인가

`NB_RFM`의 실제 고객 비중과 구매금액 기여도를 보고 대상 그룹과 실행 방법을 정한다. 비용·마진·반응 데이터가 없다면 관측한 금액 비중과 기대 효과의 가설을 구분해 말한다. 인사이트마다 근거가 되는 표·차트, 대상·실행 방법·기대 효과, 추가 데이터 또는 반증 조건을 연결한다.

예를 들어 재활성화 쿠폰을 검토할 때 구매 전환율과 고객당 마진을 발송군·미발송군에서 비교하는 검증안을 준비한다. 자연 재구매 고객에게 제공한 할인 비용과 의류의 계절성을 함께 고려한다. 특정 그룹의 우선순위와 ROI는 실제 근거를 확보한 뒤 확정한다.

### Q9. 고객 100만 명과 고해상도 이미지의 병목은 무엇인가

배열 열을 받는 호환 API의 `np.asarray(..., dtype=float)`와 실제 파일 경로의 상품별 배치 처리를 비교한다. 후자는 `utils/image_features.py`에 있으며 `image_batch_info`에 실제 배열 구조를 남긴다. RGB `1024 × 1024` 이미지 한 장의 `float64` 픽셀 배열은 `1024 × 1024 × 3 × 8 = 25,165,824`바이트, 즉 24 MiB다. 고객 수와 고유 상품 이미지 수를 구분하고, 필요한 메모리를 고유 이미지 수로 계산한다.

상품별 한 번의 피처 추출, 다운샘플링, `float32`, 배치 크기 제한, 거래 CSV 청크 처리를 개선 순서로 설명한다. 예를 들어 `32 × 32 × 3`의 `float32` 이미지 32장 자체는 384 KiB이며, 전체 사용량에는 디코딩·배치 생성 중간 배열도 포함된다. 고해상도 상태에서 큰 배치 크기를 먼저 고정하지 않는다.

### Q10. 예측 모델로 확장하면 타겟과 피처는 무엇인가

기준시점 T까지의 거래로 RFM과 고객별 상품 선호 피처를 만들고, T 이후 30일 같은 관찰 구간의 구매 여부 또는 구매금액을 타겟으로 정의하는 방안을 설명한다. 타겟 구간이 끝까지 관측되지 않은 고객은 학습 대상에서 분리한다. 상품 이미지·텍스트 피처는 고객 단위로 집계하고 관측 이미지 비율도 함께 기록한다.

향후 30일 구매금액은 해당 기간의 예측 타겟으로 명명한다. 고객 생애가치에 관한 주장은 별도의 기간·비용·유지율 정의가 필요하다. H&M의 `Monetary / Frequency`는 여기서 정의한 구매일당 금액이며 주문당 객단가와 해석 범위가 다르다. 시간순 학습·평가 분리와 미래 거래가 피처에 섞이는지 확인하는 방법을 답변한다.

### Q11. 분석 의사결정을 노트북에 어떻게 남기는가

결측치 대치 대상, IQR 배수, 이미지 표본, RFM 기준일·점수 규칙, 캠페인 대상을 정한 단계마다 선택 이유와 해당 입력의 수치 근거를 기록한다. 각 주요 해석에는 수치 1개 이상과 시사점 1문장 이상을 넣는다. 결정이 바뀌면 원인과 전후 검증 결과를 같은 구간에서 설명하고 관련 QA 답변도 갱신한다.

평가 준비는 세부 문항 19개의 증거 위치가 체크표에 기록되고, 해당 코드와 실행 결과를 직접 보여주며 Q1~Q11에 답할 수 있을 때 완료로 판단한다.
