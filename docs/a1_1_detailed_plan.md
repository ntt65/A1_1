## P0. 시작 전 실행 환경 확인

이 PC에는 Python 3.11이 설치되어 있다. 기본 `python`은 3.15를 가리키고 분석 패키지가 설치되어 있지 않으므로, 저장소 루트에서 `py -3.11 -m venv .venv`로 실행 환경을 만든다. 이후 `.venv\Scripts\python.exe`로 `requirements.txt`를 설치하고, 노트북 실행 도구는 별도로 설치한다. 네 분석 패키지의 import와 노트북 커널의 `sys.executable`이 같은 `.venv`를 가리키는지 확인한다. Jupyter가 사용자 설정 폴더에 쓸 수 없는 환경에서는 `JUPYTER_CONFIG_DIR`과 `JUPYTER_RUNTIME_DIR`을 `.venv` 아래의 쓰기 가능한 폴더로 지정한다. 현재 `.venv`는 Git에서 제외되어 있다.

## A. 데이터 선정과 검증

2. [표본 추출 노트북](../notebooks/prepare_hm_sample.ipynb)을 비공개 Kaggle Notebook으로 가져온다. A3에 따라 구매 행과 상품 이미지를 선별하고 `/kaggle/working/hm_sample.zip`에 저장한다. 다운로드 전에 파일 목록과 압축·해제 용량을 확인하고, 규정상 허용되는 표본 결과 파일만 로컬 `data/raw/hm/`에 받는다. 전체 대회 묶음, 거래 원본 CSV, 전체 이미지 폴더는 Kaggle 입력으로만 사용한다. 공식 CLI의 `download -f`는 파일 전체를 받는 방식이므로 거래 행 표본 추출에 사용하지 않는다. [Kaggle 파일 다운로드](https://github.com/Kaggle/kaggle-cli/blob/main/docs/competitions.md#kaggle-competitions-download) · [노트북 결과 다운로드](https://github.com/Kaggle/kaggle-cli/blob/main/docs/kernels.md#kaggle-kernels-output)
3. `.gitignore`에 `/data/`가 적용되어 있다. 내려받기 전에 `git check-ignore data/raw/hm/hm_sample.zip`과 `git ls-files -- data`로 제외 여부와 추적 파일이 없음을 확인한다. 표본 ZIP과 압축을 푼 파일, 중간 결과는 `data/`에 둔다.
4. 대회 규정을 기준으로 비공개 표본의 로컬 사용 범위와 GitHub에 올릴 코드·집계 표·차트·README 수치의 공개 범위를 구분해 기록한다. GitHub에 실행된 집계 결과를 제출할 수 있는 조건까지 확인되어야 최종 채택한다. [H&M 대회 규정 7·8절](https://www.kaggle.com/c/h-and-m-personalized-fashion-recommendations/rules)

첫 확인에서 접근·용량·공개 범위가 해결되지 않으면 원인을 기록하고 기본 계획의 UCI Online Retail과 Amazon Berkeley Objects 조합을 검토한다. 별도 데이터로 상품 피처와 RFM을 분석하는 구성이 평가 기준에 허용될 때만 전환한다. 이 경우 UCI의 `InvoiceNo`를 주문 ID로, `UnitPrice × Quantity`를 금액으로 사용하고 취소·반품은 양의 구매 집계와 분리한다. 상품 분석은 ABO의 자체 상품 ID와 이미지 연결을 사용한다. 제출 가능한 데이터가 확정되기 전에는 검증용 입력으로 모듈의 계산만 점검하고, 실데이터 채택 항목은 미완료로 둔다.

### A2. 입력 구조 고정

H&M 채택 시 표본 ZIP에 아래 파일을 담는다. 첫 샘플을 읽어 실제 파일명과 열 이름을 대조한 뒤 README에 확정값을 기록한다.

| 입력 | 로컬 경로 | 분석용 열과 단위 |
| --- | --- | --- |
| 구매 내역 | `data/raw/hm/transactions_sample.csv` | 선택 고객의 유효 구매 상품 행. `customer_id`, `article_id`, `order_date` (`t_dat`), `amount` (`price`), `sales_channel_id` |
| 상품 목록 | `data/raw/hm/articles_sample.csv` | 표본 거래의 `article_id`별 한 행. `product_name` (`prod_name`), `category` (`product_type_name`), 원본 이미지 유무 및 표본 포함 여부 |
| 이미지 | `data/raw/hm/images/` | 거래에 등장한 상품 중 선별한 JPG. 파일이 없는 상품과 표본에서 뺀 상품을 구분 |
| 추출 기록 | `data/raw/hm/sample_manifest.json` | 출처, 기간·채널·시드, 표본 추출 전 기준일, 거래 제외 집계, 이미지 상태별 건수 |

고객·상품·주문 ID는 문자열로 유지하고 공백만 있는 ID는 결측으로 처리한다. 날짜는 원본 형식을 지정해 달력일로 변환하고, 금액은 유한한 수로 변환한다. H&M은 `sales_channel_id`의 의미를 출처에서 확인한 후 온라인 구매를 분석 대상으로 삼는다. 온라인 채널을 확인할 수 없으면 전체 채널을 사용하고 결과 범위를 전체 채널로 표시한다. 분석용 거래 테이블에는 위 거래 열 5개, 상품명과 카테고리, 이미지 처리 상태가 들어가도록 한다. 이미지 배열은 상품 단위 배치에서 처리하고, 계산한 피처를 상품 ID로 연결한다.

### A3. 관찰 기간과 표본 고정

1. 거래 범위에서 완전한 달 3개 이상을 연속으로 선택한다. 양끝 달의 수집 범위가 확인되지 않으면 제외한다. 시작일 포함, 종료일 제외 규칙을 적용하고 선택한 기간을 기록한다.
2. Kaggle Notebook에서 `transactions_train.csv`의 필요한 열만 Pandas `usecols`와 `chunksize`로 읽는다. 첫 순회에서 기간·채널·유효성 조건을 만족하는 고객 ID와 마지막 거래일을 수집한다. 정렬한 고객 ID에서 시드 `42`로 처음에는 최대 1,000명을 선택하고, 두 번째 순회에서 선택 고객의 기간 내 유효 거래를 모두 추출해 청크별로 저장한다. 유효 거래 1,000건 또는 세그먼트 4개를 확보하기 어려우면 표본 규모나 기간을 늘려 다시 검증한다.
3. 선택 거래에 포함된 상품의 메타데이터만 내보내고, 해당 상품 중 실제 파일이 있는 이미지에서 처음에는 최대 200장을 고정 시드로 선별한다. 이미지 표본 선정은 RFM 고객·거래 표본과 분리한다. 파일 없음과 표본 미포함은 추출 단계에서, 읽기 성공과 손상은 이미지 처리 단계에서 구분한다. 고객 메타데이터 `customers.csv`는 RFM 집계에 쓰이지 않는다.

### A4. 실데이터 채택 판정

정제 후 유효 거래 1,000건 이상, 분석용 테이블 8개 이상 열, 수치·범주·날짜 등 최소 3가지 유형을 확인한다. 실제 상품명과 이미지 배열이 상품 ID 기준으로 연결되는지 확인하고, 이미지 산점도와 상관계수에 사용할 서로 다른 관측값이 있는지도 점검한다. 초기 결과에 원본 기간, 최종 기간, 고객 수, 거래 수, 상품 수, 조인 일치율과 이미지 읽기 성공률을 남긴다. 구매 금액의 화폐 단위가 확인되지 않으면 원본 단위로 보고한다.

## B. 로드와 멀티모달 피처

### B1. `DataAnalyzer` 입출력 연결

`src/pipeline.py`의 `DataAnalyzer`에 로드·결측치 대치·IQR 탐지·RFM 계산 메서드를 유지하고 대치 전략, 대상 열, IQR 배수와 기준일을 인자로 받는다. 실제 분석에 필요한 열과 ID 자료형을 명시하고, 필수 열이 빠졌거나 입력이 비었으면 경로 또는 누락 열을 오류에 표시한다. `--data`는 CSV 로드 확인에 사용한다. 노트북은 클래스 메서드를 호출해 분석을 진행한다. 관찰 기간, 시드, 데이터 경로 등 실험 설정은 저장소 기준 상대 경로를 사용하는 설정 셀 한 곳에 둔다.

### B2. 상품 조인과 분석 단위 분리

거래에서 상품으로 `article_id` 기준 다대일 왼쪽 조인을 한다. 상품 목록의 비어 있는 키는 조인 대상에서 제외하고, 중복 키는 원인을 확인한 뒤 처리 규칙을 기록한다. 미매칭 거래는 별도로 집계한다. 조인 전후 거래 행 수는 정확히 비교하고 금액 합계는 문서화한 부동소수점 허용 오차로 대조한다. 구매와 월별 추세는 거래 단위, 이미지·텍스트 관계는 상품 단위, RFM은 고객 단위에서 계산한다.

### B3. 이미지 피처 연결

상품 ID별 이미지를 `matplotlib.image.imread()`로 한 번 읽는다. 회색조는 RGB 세 채널로 펼치고, 알파 채널이 있으면 RGB 세 채널을 사용한다. 정수 픽셀은 자료형의 최대값으로 나눠 0~1 범위로 맞추고, 이미 0~1인 실수 픽셀은 원래 값을 사용한다. NumPy 인덱싱으로 기본 `32 × 32 × 3` 크기로 다운샘플링한다. 누락·손상·최소 크기 미달 이미지는 건수를 기록하고 피처를 결측으로 둔다. 읽기 성공 이미지를 같은 모양의 배치로 쌓아 기존 `extract_image_features()`의 축 연산으로 이미지당 평균과 표준편차를 계산한다. 산출된 두 피처를 상품별 새 열로 연결한다. 메모리가 부족하면 배치 크기를 줄인다.

### B4. 텍스트 피처와 입력 검증

`extract_text_features()`로 상품명 길이와 공백 기준 단어 수를 구한다. 누락 상품명을 빈 문자열로 처리하기 전에 원래 결측 수를 기록한다. 작은 입력에서 `"Blue cotton shirt"`의 길이 17과 단어 수 3을 확인한다. 픽셀 값의 절반이 0이고 절반이 1인 배열에서 이미지 평균과 표준편차가 각각 0.5인지 확인하고, 회색조·RGB·읽기 실패 이미지도 검증한다.

## C. 정제와 RFM 집계

### C1. 유효 거래 분리

대표 제외 사유는 고객 ID 누락 → 날짜 오류 → 주문 모드의 주문 ID 누락·취소 → 비유한·변환 불가·0 이하 금액 순으로 기록한다. 정제에서 유효한 거래 중 분석 기간·채널 밖 거래와 표본 미선택 거래는 별도로 센다. H&M은 Kaggle에서 `원본 행 수 = 정제 제외 + 범위 제외 + 표본 제외 + 표본에 남긴 거래`를 확인해 추출 기록에 남긴다. 로컬에서는 CSV 행 수와 추출 기록을 대조하고, 분석 입력의 유효성을 재검증한다. 동일 값의 H&M 구매 행은 유지한다. 상품·이미지 미매칭은 구매 유효성 판정과 분리하고, RFM과 월별 추세는 같은 유효 구매금액 원값을 사용한다. 유효 거래가 비면 집계를 중단하고 사유를 표시한다.

### C2. 그룹별 결측치 대치

`handle_missing_values()`의 그룹 평균을 지정한 수치 피처에만 적용한다. 예를 들어 분석용 이미지 평균 사본에 카테고리별 평균을 적용하고, 그룹 평균이 없으면 해당 피처의 전체 평균을 사용한다. 표본에 포함되지 않은 이미지의 값은 대치 대상에서 제외한다. 전체가 결측인 피처는 결측으로 두고 보고한다. 원본 이미지 피처와 기존 관측값은 보존한다. 대치 전후 결측 수와 카테고리 평균·전체 평균이 각각 채운 건수를 확인한다. 실제 결측이 없으면 별도 시연용 사본에 표시한 결측을 만들어 대치 결과를 보여주고, 본 분석에서는 관측값을 사용한다.

작은 입력에서 A 카테고리의 `[10, 30, 결측]`은 `20`으로 채우고, 카테고리 누락 행의 관측값 `50`은 유지한다. 이 세 관측값만 있을 때 그룹 평균이 없는 행의 결측은 전체 평균 `30`으로 채워지는지 확인한다.

### C3. IQR 탐지와 분포 보정

`detect_outliers()`에서 유효한 수치로 Q1과 Q3를 구하고, `IQR = Q3 − Q1`, 기본 임계 배수 `1.5`로 하한과 상한을 계산한다. 경계와 같은 값은 정상 범위에 포함한다. EDA용 사본의 값만 상하한으로 보정해 원본과 비교한다. `[1, 2, 3, 4, 100]`에서 경계는 `−1`, `7`이고 `100`만 탐지된다. `[−2, 1, 2, 3, 6]`에서는 양쪽 경계값이 탐지되지 않아야 한다. 금액에서 이상치가 0건이거나 IQR이 0이면 그 결과를 기록한다. 전후 비교가 가능한 다른 수치 변수가 있으면 해당 변수로 박스플롯을 작성한다.

### C4. RFM 지표와 점수 산출

| 지표 | 집계 규칙 |
| --- | --- |
| `Recency` | A3에서 정한 기준일과 고객 최종 구매일의 달력일 차이. 기준일 구매는 0일 |
| `Frequency` | H&M은 고객별 고유 구매일 수. 주문 ID가 있는 입력에서는 고유 주문 수 |
| `Monetary` | 고객별 유효 구매금액 원값의 합계 |

기준일은 기간·채널 내 마지막 유효 거래일로 정하고 같은 범위에서 표본 크기를 바꿀 때도 유지한다. 기준일이 입력 거래의 최종일보다 앞서면 오류를 표시한다. R은 Recency 내림차순, F와 M은 각 지표 오름차순으로 평균 순위를 매긴다. 고객 수를 `n`이라 할 때 `(평균 순위 − 0.5) / n`을 계산한다. 이 값이 0.25 이하이면 1점, 0.50 이하이면 2점, 0.75 이하이면 3점, 그보다 크면 4점이다. 동일값은 같은 점수를 받고, 데이터가 한 값에 몰려 일부 점수가 비면 그 분포를 기록한다. 행 순서를 바꿔도 동일 고객의 지표와 점수가 같은지 확인한다.

집계 검증용으로 A 고객이 1월 1일에 `10`, `20`, 1월 3일에 `30`을 구매하고 B 고객이 1월 2일에 `5`를 구매한 입력을 사용한다. 1월 3일을 기준으로 A의 R·F·M은 `0·2·60`, B는 `1·1·5`다. 전체 고객의 Monetary 합계는 `65`다. 주문 모드에서는 같은 주문의 상품 행 여러 개가 한 주문으로 집계되는 경우도 확인한다.

### C5. 고객 세그먼트 분류

아래는 실데이터 검토 전의 초기 규칙이다. 위에서부터 처음 일치한 그룹에 배정한다. `R`, `F`, `M`은 점수이며 구매 횟수는 C4에서 정한 Frequency 원값이다.

| 우선순위 | 그룹 | 초기 조건 |
| --- | --- | --- |
| 1 | `VIP` | R·F·M이 모두 3점 이상이고 구매 횟수 2회 이상 |
| 2 | `Loyal` | R·F가 3점 이상이고 구매 횟수 2회 이상 |
| 3 | `New` | R이 3점 이상이고 관찰 기간 내 구매 횟수 1회 |
| 4 | `Churned` | R이 2점 이하인 이탈 위험 고객 |
| 5 | `Potential` | 위 조건에 해당하지 않는 고객 |

전체 유효 고객이 한 그룹에만 속하고, 고객이 있는 그룹이 최소 4개인지 확인한다. 부족하면 먼저 점수별 고객 수와 최초 분류표를 저장하고, 관찰 기간이나 표본 규모를 넓혀 다시 확인한다. 낮은 최근성 그룹에 과거 반복 구매 고객과 1회 구매 고객이 모두 있다면, 재활성화 전략의 차이를 근거로 해당 그룹을 두 그룹으로 나누는 규칙을 검토한다. 규칙 변경 시 이전·이후의 고객 수와 금액 비중을 남긴다. 미션 기준인 4개 그룹을 충족할 때까지 C5를 미완료로 둔다. `New`는 기간 내에 한 번 구매가 관측된 고객이며, `Churned`는 낮은 최근성을 기준으로 분류한다.

## D. 분석 노트북 작성

### D1. 데이터 탐색과 처리 과정 표시

`notebooks/analysis_report.ipynb`를 **설정 → 데이터 탐색 → 피처 생성 → 결측과 이상치 → 통계와 RFM → 차트와 해석** 순서로 실행할 수 있게 구성한다. `head()`, `info()`, `describe()`로 구조를 확인하고 정제 단계의 건수와 변화량을 출력한다. 공개본에서는 `head()` 예시 행을 공개가 허용된 열로 제한한다. 행 단위 공개가 제한되면 예시 행은 가상 입력임을 명시하고, 실제 데이터의 구조와 통계는 공개가 확인된 요약으로 보여준다.

### D2. 요약 통계와 상관계수

`DataAnalyzer`에 요약 통계 메서드를 두고 거래금액과 주요 피처의 평균, 중앙값, 표준편차와 사분위수를 출력한다. 상품 단위에서 관측 이미지의 평균과 표준편차, 고객 단위에서 Frequency와 Monetary의 피어슨 상관계수를 계산한다. 쌍별 유효 표본 수와 계수를 기록한다. 표본이나 분산이 부족하면 유효한 다른 쌍을 선택하고 이유를 적는다. Frequency와 Monetary의 관계를 해석할 때 두 지표가 모두 같은 구매 기록에서 집계된다는 점을 고려한다. 탐색과 주요 통계 해석마다 **관측 수치 하나 이상과 시사점 한 문장 이상**을 붙인다.

### D3. 필수 차트 6종

| 차트 | 입력 단위와 축 | 확인할 내용 |
| --- | --- | --- |
| 히스토그램 | 거래. 금액 × 건수 | 집중 구간과 꼬리 |
| 박스플롯 | 거래. 보정 여부 × 금액 | 같은 값의 IQR 보정 전후를 동일 축으로 비교 |
| 막대그래프 | 고객. 세그먼트 × 고객 수 | 세그먼트 크기 |
| 히트맵 | 고객. RFM 변수 × RFM 변수 | 상관계수의 방향과 크기 |
| 산점도 | 상품. 관측 이미지 평균 × 관측 이미지 표준편차 | 이미지 특성의 분포와 관계 |
| 라인차트 | 월. 완전한 월 × 유효 구매금액 합계 | 선택 기간과 표본 안에서의 월별 변화 |

모든 차트에 제목, 축 레이블과 해당 단위를 표시한다. 이미지 산점도와 이미지 상관계수에는 관측 피처를 사용한다. 라인차트에서 선택된 완전한 월은 빠짐없이 표시하고, 데이터가 확인된 달에 표본 구매가 0건이면 합계를 0으로 표시한다. 월별 금액 합계는 유효 거래 금액 합계와 대조한다.

### D4. 세그먼트 프로파일 비교

세그먼트마다 고객 수와 비중, Recency와 Frequency 중앙값, 고객당 Monetary, 전체 구매금액 비중을 한 표에 표시한다. 고객 수 합계를 유효 고객 수와, 금액 합계를 RFM 입력 금액과 대조한다. 고객 구성과 구매금액 기여가 어떻게 다른지 수치로 설명한다.
